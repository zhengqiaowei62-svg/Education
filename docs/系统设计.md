## 3. 关键数据流

### 3.1 上传 → 抽取 → 融合

```
PDF ─▶ /api/upload ─▶ pdf_parser ─▶ Textbook(chapters/blocks/images) ─▶ state.TEXTBOOKS
                                                                          │
                                                /api/graph/extract ◀──────┘
                                                          │
                                                Extractor Agent ─▶ KGGraph ─▶ state.GRAPHS[id]
                                                          │
                                            /api/graph/merge (≥2 books)
                                                          │
                                                  Judge Agent ─▶ state.MERGED_GRAPH
                                                          │
                                                  写入 report/整合报告.md
```

### 3.2 RAG 问答（关键流水线）

```
question ─┐
          ├─▶ _bm25(question)         (词项倒排打分)
state.    ├─▶ _semantic(question)     (BGE 余弦；不可用回退 hash)
CHUNKS  ──┤
          └─▶ _region(question)       (按 chunk metadata 章/页/坐标加权)

   ┌─────────────────────────────────┐
   │  _rrf(channels, rrf_pool=15)    │  Reciprocal Rank Fusion
   └────────────────┬────────────────┘
                    ▼
   ┌─────────────────────────────────┐
   │  _rerank(question, candidates)  │  ① BGE 精排分 ② MMR 多样性
   └────────────────┬────────────────┘
                    ▼
       prompt = history + system + retrieved
                    │
                    ▼
   utils.llm.chat(role="judge", stream=True)
                    │
                    ▼
       answer + Citation[]   ─▶ 前端可点回原文
```

### 3.3 HITL 修订

前端"双击节点改名"或"Shift+拖拽合并"或对话区直接说"把 X 拆成两个" →
统一调用 `POST /api/graph/modify`，由 `graph._execute_modification(instruction)`：

1. 调 Extractor 把自然语言映射成 `{action, payload}`；
2. 在 `state.MERGED_GRAPH` 上原子地执行；
3. 落盘 `state.MODIFICATIONS`（审计），返回 message。

## 4. 数据模型（schemas.py 摘要）

```python
class KGNode(BaseModel):
    id: str; name: str; category: str
    definition: str = ""; textbook_id: str = ""
    page: Optional[int] = None
    bbox: Optional[List[float]] = None

class KGEdge(BaseModel):
    source: str; target: str
    relation_type: Literal['prerequisite','parallel','contains','applies_to']
    evidence: str = ""

class Citation(BaseModel):
    chunk_id: str; textbook: str; chapter: str = ""
    page: Optional[int]; page_end: Optional[int]
    relevance_score: float; bbox: Optional[List[float]]
    block_ids: List[str] = []; quote: str = ""
    source_url: Optional[str] = None
    retrieval_mode: str = "hybrid"

class RagQueryRequest(BaseModel):
    question: str; top_k: int = 5
    search_mode: Literal['hybrid','term','semantic','region'] = 'hybrid'
    history: List[dict] = []
```

## 5. 检索算法细节

### 5.1 向量召回

- 模型：`BAAI/bge-small-zh-v1.5`（512 维），由 `_get_st_model()` 懒加载；
- 不可用时（无 sentence-transformers / 离线）回退 `_hash_embed`：哈希分桶 + L2 归一化；
- 余弦：`vecs @ q_vec[0]`（numpy 矩阵乘法）。

### 5.2 RRF 融合

$$
\text{RRF}(d) = \sum_{c \in \text{channels}} \frac{1}{k + \text{rank}_c(d)},\ k = 60
$$

### 5.3 Rerank（创新点）

候选 $D = \{d_1,\dots,d_N\}$，BGE 精排分 $s_i$，MMR：

$$
d^* = \arg\max_{d_i \in D \setminus S}\big[\lambda\,s_i - (1-\lambda)\,\max_{d_j \in S}\text{sim}(d_i,d_j)\big]
$$

实现于 [`backend/core/rag_pipeline.py`](../backend/core/rag_pipeline.py) `_rerank()`，$\lambda = 0.7$。

## 6. 部署设计

### 6.1 本地

`uvicorn` 直接跑后端；`vite` 跑前端，dev proxy `/api` → `127.0.0.1:8000`（见 `frontend/vite.config.js`）。

### 6.2 Docker（生产）

- `Dockerfile`：python:3.11-slim + 依赖 + `uvicorn backend.main:app --host 0.0.0.0`；
- `frontend/Dockerfile`：node:20 build → nginx:alpine 提供静态 + `nginx.conf` 反代 `/api/` 到 `backend:8000`；
- `docker-compose.yml`：定义 `backend`、`frontend` 两服务 + `report` 卷持久化。

## 7. 配置与可观测

- `.env.example` 是唯一配置入口（API Key / 模型 / 端口 / RAG 超参）；
- 后端启动会打印每个 Agent 的 base_url + model + key 是否就位；
- `/api/stats/tokens` 自动记录每次 LLM 调用（优先 SDK `usage`，缺失时近似估算）；

## 9. 技术选型理由

| 选型 | 备选 | 选择原因 |
| --- | --- | --- |
| FastAPI | Flask / Django | 类型校验 + OpenAPI 自动生成；与 Pydantic schema 配合 |
| 内存态 + JSON | Postgres / Redis | MVP 阶段降低部署复杂度，后续替换不影响接口 |
| AntV G6 | D3 / vis-network | 企业级布局算法、TreeGraph 现成、自定义形状方便 |
| BGE-small-zh | text2vec / m3e | 中文表现优、512 维平衡精度/速度、可商用 |
| Ollama 兼容 | 自实现 HTTP | OpenAI 协议复用现有 chat() 实现，0 改动 |
| weasyprint | wkhtmltopdf / reportlab | 纯 Python；中文字体易解决；CSS 渲染 |
| RRF + MMR | 仅 BM25 / 仅向量 | RRF 抗单通道偏差；MMR 抑制重复 chunk |

—

## 10. 演进路线

- 替换内存态为 SQLite/Postgres + 向量库（pgvector）；
- 增加多用户与权限；
- Sankey 视图（基于现有 G6 数据可在 1~2 小时内增加）；
- Benchmark 数据集自动生成（用 LLM 反向出题 + 教师审核）；
- 把 Extractor / Judge / Vision 做成独立 worker（celery）便于水平扩展。
